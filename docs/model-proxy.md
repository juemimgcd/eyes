# 模型协议透视

Eyes 可通过本地模型代理采集 Chat Completions 请求与响应，无需导入 Agent 源码。此实现迁移自 Attacker 的模型代理与流式解析器；许可见 `src/eyes/tracing/LICENSE.attacker`。

## 使用

在「Agent 观测」中创建观测来源，将返回的来源令牌设置为 `EYES_OBSERVATION_TOKEN`。将 API 根地址设置为 `EYES_OBSERVATION_URL`，公网部署须包含实际 API 前缀，例如 `https://your-host/eyes/api`。

```sh
uv run eyes trace proxy \
  --upstream-base-url https://your-model-provider/v1 \
  --output-dir .eyes/model-proxy
```

把 Agent 的模型 base URL 改成 `http://127.0.0.1:8787/v1`，保留模型名称与模型 API Key。这里的上游地址是占位示例，需填写原模型服务的实际地址。代理仅监听回环地址。

启动代理即启用请求与响应正文采集。内置敏感字段及请求中的认证值会脱敏，可重复传入 `--redact-field customer_name` 指定额外字段；业务隐私需按实际输入配置。不要提交或共享 `.eyes/` 目录。

## 查看

在既有「Agent 观测」列表中查看 `model-proxy (模型请求观测)`。每个模型请求是一条独立记录，**不是整个 Agent 任务**。开始事件可在执行期间上传；响应在该请求结束或中断后整理，页面沿用现有轮询刷新。点击模型节点查看请求、回复和模型提出的工具调用；下一次请求中的工具结果显示为 Agent 回传结果，不代表代理观察了工具真实执行。

同一任务可设置 `X-Eyes-Trace-ID` 请求头，该头仅供代理关联，不转发到模型。没有显式标识时，仅依据已观察到且唯一匹配的工具调用引用关联；无法关联则保留独立会话。关联缓存有界且仅保存在代理进程中，重启后不会恢复。不得将观测时间排序理解为并行任务的依赖关系。

## 传输与范围

代理原样转发请求正文和响应流，不执行工具、不自动重试模型请求。每两秒尝试上传已落盘且尚未确认的观测批次；开始批次确认后写入 `.ack` 摘要，内容未变化时不再重传。只有当前代理进程仍在处理的请求发送心跳。进程重启后，遗留开始记录不会持续刷新活跃时间，也不会自动补造终态。云端确认终态批次后删除对应本地文件及确认记录。网络、认证、限流及服务端故障保留队列，下一轮重试；非法批次以及服务端返回 400/409/413/422 的批次移入 `rejected/` 并保存诊断，后续正常批次继续上传。修复原因后可将批次移回原目录重传，诊断文件不要移入队列根目录。停止代理后也可重传：

```sh
uv run eyes trace upload --output-dir .eyes/model-proxy
```

每个代理实例使用独立目录；上传到原来的来源与项目。不要在代理运行期间同时启动独立 upload 进程。磁盘目录应由用户管理容量；磁盘写入失败会记录错误，不能保证未落盘数据恢复。进程崩溃留下的开始记录不会自动推断执行成功。

当前支持 `/v1/chat/completions` 的 JSON 与 SSE 响应，不支持 Responses、Anthropic 或模型列表接口。响应采集上限 1 MiB，单事件正文超过 20 KB 会显示截断预览；截断或不完整协议响应标记为不完整证据，转发仍继续。模型回复不是逐 token 发布到 Eyes。

覆盖标记为 `model_protocol_only`：可观察模型上下文、工具定义、模型请求调用、Agent 回传结果及模型响应。未经过代理的请求、本地函数、真实工具耗时、远端副作用与隐藏推理不在范围内。这里只加入模型代理，未迁移 Attacker 的 Python 函数包装，也不修改连接或任务调度功能。

模型节点的失败状态映射为现有 `ERROR` 格式，保留错误类型、HTTP 状态及有长度限制的上游错误。上游返回的 Token 用量映射为 Eyes 的输入、输出与总量字段，未提供的字段不补零。SSE 已解析到完整 `[DONE]` 后，客户端关闭连接不会将已完成的模型响应改为取消；传输异常仍保留在原始事件中。
